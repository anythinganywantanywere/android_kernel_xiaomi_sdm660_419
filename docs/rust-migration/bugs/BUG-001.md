# BUG-001: strcpy tanpa batas dari string device tree ke eeprom_name[128]

- File/fungsi: `drivers/media/platform/msm/camera_v2-legacy/sensor/eeprom/msm_eeprom.c`, fungsi probe EEPROM, blok `#ifdef CONFIG_MACH_LONGCHEER` (sekitar baris 2024 di tree ini; nomor baris bisa bergeser, cari `strcpy(s_vendor_eeprom[pdev->id].eeprom_name`)
- Jenis: overflow (potensi, bukan terbukti tereksploitasi)
- Bagaimana ditemukan: grep terarah `strcpy`/`sprintf` di kandidat §9.2, lalu penelaahan manual definisi struct dan sumber string
- Terjangkau dari: device tree saja (privileged / rantai boot), bukan aplikasi dan bukan jaringan
- Bukti:
  - Tujuan: `s_vendor_eeprom[pdev->id].eeprom_name`, dengan `struct vendor_eeprom { char eeprom_name[128]; uint8_t module_id; }` di `include/soc/qcom/camera2-legacy.h`, dan `CAMERA_VENDOR_EEPROM_COUNT_MAX 14`.
  - Sumber: `eb_info->eeprom_name`, yaitu pointer string dari `of_property_read_string(of_node, "qcom,eeprom-name", ...)` — panjangnya ditentukan isi device tree, tidak dibatasi 128 di kode ini.
  - Tidak ada pemeriksaan panjang sebelum `strcpy` di blok ini. (Perlu dicatat: di jalur ioctl `CFG_EEPROM_GET_INFO` yang lain di file yang sama, panjang nama memang diperiksa terhadap `MAX_EEPROM_NAME` 32 sebelum `memcpy` — pemeriksaan itu tidak ada di jalur probe LONGCHEER ini.)
  - File ini **terbangun** untuk whyred-perf: `out-fase1/.../camera_v2-legacy/sensor/eeprom/msm_eeprom.o` ada, dan `CONFIG_MACH_LONGCHEER=y` di `.config` Fase 1.
  - Catatan kedua yang belum diperbaiki di sini: `pdev->id` juga tidak diperiksa terhadap 14 di blok ini. Itu kandidat terpisah, bukan bagian dari perbaikan BUG-001, dan tidak diklaim sebagai bug terbukti karena ID platform ditetapkan oleh registrasi board, bukan input aplikasi.
- Status upstream: belum diketahui; ini kode vendor LONGCHEER, bukan kode upstream yang bisa dicocokkan ke stable 4.19.325. Tidak ada CVE yang diverifikasi untuk pola ini.
- Rencana perbaikan: patch minimal di C — ganti `strcpy` menjadi `strlcpy` dengan ukuran tujuan (`sizeof(s_vendor_eeprom[pdev->id].eeprom_name)`). Nama yang lebih panjang dari 127 karakter akan terpotong, bukan meluber. Itu perubahan perilaku yang aman untuk nama EEPROM normal (jauh di bawah 128). Lihat Fase 4.
- Catatan: pola yang sama ada di `camera_v2` (non-legacy) di baris sekitar 2007, tetapi file itu **tidak terbangun** untuk whyred-perf (tidak ada `.o` di `out-fase1` untuk `camera_v2/sensor/eeprom`), jadi perbaikan Fase 4 hanya menyentuh file legacy yang terbangun, dan pola di `camera_v2` dicatat di sini sebagai tindak lanjut bila driver itu diaktifkan.
- Tidak ada exploit atau PoC yang ditulis untuk temuan ini.
